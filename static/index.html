Linux agent installation

1. Enroll a node. 2. Save its token once. 3. Install agent/agent.py and the systemd unit. 4. Configure CF_SERVER_URL, CF_NODE_ID and CF_NODE_TOKEN in /etc/cyberforge-node/agent.env. 5. Enable the service.

sudo systemctl enable --now cyberforge-node.service

Continuous telemetry ingestion

Use a dedicated sensor token and the checkpointed JSONL follower. It starts at end-of-file by default, resumes after restart and follows rename-based log rotation.

python server.py create-token --name falco-tail --role sensor
python tools/tail_jsonl.py --source falco --server https://YOUR-CYBERFORGE-HOST --input /var/log/falco/events.jsonl --token-file /etc/cyberforge-server/falco.token
Trivy reports remain batch-based. Store checkpoint files on persistent local storage with mode 0600; the shipper skips malformed lines without logging their content.

Ingestion token

Create a dedicated token with role sensor. Do not use an administrator token in log shippers.

python server.py create-token --name suricata-shipper --role sensor
python tools/ingest_jsonl.py --source suricata --server https://YOUR-CYBERFORGE-HOST --input /var/log/suricata/eve.json
Endpoint: POST /api/v204/security/ingest/{source}. Remote server URL must use HTTPS. The shipper does not follow redirects.

Source and data handling

STIX parsing currently supports a bounded subset of observable equality patterns. TAXII requests are explicit, redirect-free and limited to allowlisted HTTPS hosts. Raw feed payloads are not stored as general-purpose executable content.
Check each feed's license and fair-use terms before enabling it in commercial environments. Feed matches are indicators, not proof of compromise.
CyberForge rules use a bounded, data-only normalized-event format. No regex, scripts or arbitrary expressions are executed. Publishing requires a different authorized API actor label; this is not human identity verification.
