# User Control, Customization and Permissions

CyberForge is designed to let the local user control the application's preferences and default operating mode.

## You can customize

- Theme, accent color, density, type scale and sidebar width.
- Editor font, font size, tab size, word wrap, autosave and line-number preference.
- AI communication style, optimization goal, custom instructions and autonomy preference.
- Whether local static analysis, attached diagnostics and detailed report persistence are automatic.
- Per-capability policy using Allow / Ask / Deny.
- Profile export/import and reset to defaults.

The current release exposes **20 registered capabilities**: `project_read`, `project_write`, `knowledge_access`, `static_analysis`, `local_lint`, `code_execution`, `ai_provider_access`, `network_connectors`, `system_network_changes`, `dynamic_analysis`, `plugin_execution`, `evidence_write`, `case_read`, `case_write`, `evidence_read`, `connector_config`, `vault_admin`, `plugin_admin`, `engine_admin` and `host_app_launch`.

## What the policies mean

- **Allow:** The named CyberForge capability is granted by the persistent local profile.
- **Ask:** A specific request must include the acknowledgement generated by an explicit user action. Engine package installation/version changes use `engine_admin`; plugin install/update/remove/authorization use `plugin_admin`; plugin execution separately uses `plugin_execution`.
- **Deny:** The backend rejects that capability. AI autonomy mode, including `trusted`, cannot override `Deny`.

The app validates capability names and profile keys. A profile cannot add arbitrary new API capabilities by importing JSON.

## Why some controls remain

The permission profile controls CyberForge features; it does not and cannot remove operating-system permissions, file-system ownership, provider authentication, network routing constraints, or external service confirmation. The application does not provide cloud AI with a free-form host shell or arbitrary filesystem access. It does not silently execute AI-generated code or overwrite a project without a reviewed patch.

These are not restrictions on how you customize the interface or how you want AI to communicate. They protect the boundary between an instruction and a real action on the machine.

## Cloud AI and context

When using QwenCloud/xKiro, the prompt and selected source/context can be transmitted to that provider. Keep the cloud-context acknowledgement enabled unless you have intentionally chosen otherwise. Never put secrets in custom instructions, code context, project notes or knowledge documents that you send to a cloud provider.

## Recovery

Export a profile before experiments. Back up the database and Evidence Vault before upgrades. Vault encryption passphrases must be kept separately; there is no hidden recovery backdoor.

## Engine and plugin lifecycle controls

- Engine Manager accepts only the fixed, version-pinned catalog in `plugins/README.md`. It creates one Python virtual environment per engine version under the user's data directory. It does not modify system Python, PATH, or system package managers. Installing contacts the public PyPI index after explicit acknowledgement. Previous versions remain available for switching/rollback until the user removes them.
- Plugin Manager accepts a constrained flat ZIP package, validates its manifest and archive structure, and installs it disabled with no granted permissions. Updating a plugin revokes all previous grants so the new code must be reviewed and authorized again.
- Plugin execution remains separate from installation. It requires the plugin to be enabled, the requested capabilities to be granted, a local Docker/Podman runtime with the configured image already present, and explicit run acknowledgement. No image is pulled automatically.
- SHA-256 checks package integrity only when compared with a separately trusted hash. It is not a publisher signature. Catalog package versions are pinned, but transitive dependency hashes are not currently frozen. Treat installed third-party engines as code running with the current user's OS privileges.
